## Purpose

Polish the customer-facing documentation so any customer or Sales Engineer can
fully automate CloudLens sensor deployment to AWS EC2 instances without
ambiguity, and stand up the full vController + KVO + vPB stack from the
Marketplace AMIs with one command. Three artifacts, one source of truth.

## Audience

- **Primary:** Customer DevOps / network engineers deploying sensors to their
  EC2 instances (already running Ansible).
- **Secondary:** Keysight Sales Engineers demoing the solution to enterprise
  prospects.
- **Tertiary:** Customer executives / procurement reviewing the runbook.

## Success Criteria

A customer with no prior context can:
1. Land on the GitHub README and identify their deployment path in under 30
   seconds.
2. Click Launch Stack and reach a running vController + KVO + vPB in about 20
   minutes.
3. Run a single command and have sensors deployed in under 10 minutes for a
   small (<50 instance) environment.
4. Trust the solution because verified results are visible up front.
5. Share a polished runbook with their executive team without modification.

## Design Principle

**Every page pushes the customer toward the fully-automated path.** No manual
steps beyond the ones AWS forces (Marketplace subscription, EULA acceptance).
Every section ends with a command or button they can execute.

## Artifacts

### 1. README.md (Technical "wow")

Sections in order:

1. **Hero** - value prop, then the deploy badges (Launch Stack / CloudShell /
   Docker), then status badges.
2. **One-command stack deploy** - the curl deploy-stack.sh story with the
   configuration/override table.
3. **"Which path?" decision tree** - CloudFormation / CloudShell / Docker.
4. **EC2 compatibility matrix** - OS x connection method (SSH / SSM / WinRM /
   Bastion / CloudShell).
5. **CloudFormation AND Terraform deploy sections** - both produce the same
   stack.
6. **Ansible sensor quickstart** - tag, configure, run.
7. **Scaling table** - fleet size to parallelism to wall time.
8. **Architecture summary** - sensor to KVO to VPC Traffic Mirroring to vPB.
9. **Marketplace AMI table** - the four AMIs and instance types.
10. **Footer** - docs links, support, related repos, license.

### 2. Runbooks (Executive "wow")

Two Word/PDF documents, generated by python-docx scripts:

- `CloudLens_Ansible_AWS_Customer_Runbook.docx/.pdf` - the sensor-deployment
  customer runbook (11 sections, printable checklists).
- `CloudLens_Stack_Deployment_Runbook.docx/.pdf` - the vController + KVO + vPB
  stack deployment runbook (three paths, verification, troubleshooting,
  cleanup).

Style: Keysight gold logo, AWS squid-ink (#232F3E) headers, AWS-navy table
header rows, AWS orange accents, Courier code blocks, professional layout.

### 3. Landing site (docs/)

Static GitHub Pages site (index.html + styles.css + glass.css + script.js) with
the Launch Stack quick-create button, the scaling slider, and the deployment
walkthrough screenshots.

## EC2 Compatibility Coverage

The matrix must communicate full coverage. Cells documented as supported:

| OS / Topology | Public IP + SSH | Private + Bastion | SSM (no inbound) | CloudShell |
|---|---|---|---|---|
| Ubuntu 20.04 / 22.04 / 24.04 | Yes | Yes | Yes | Yes |
| RHEL 7 / 8 / 9, Amazon Linux | Yes | Yes | Yes | Yes |
| Rocky / AlmaLinux | Yes | Yes | Yes | Yes |
| Windows Server 2019 / 2022 | Yes (WinRM) | Yes (SSM) | Yes | Yes |

Anything not yet tested gets "(planned)": honest, not aspirational.

## Decisions Locked In

- **Format:** README (Markdown) + two Word/PDF runbooks + GitHub Pages site.
- **Hero priority:** value prop, then Launch Stack / CloudShell / Docker badges,
  then status badges.
- **Runbook style:** AWS palette (squid-ink headers, orange accents) over the
  Keysight-branded layout ported from the Azure runbooks.
- **Audience:** SE-facing AND customer-facing, dual mode.
- **Automation emphasis:** every section ends with an executable command or
  button.
- **Keep the existing good AWS docs** (ARCHITECTURE, DEPLOYMENT_GUIDE, SCALING,
  TROUBLESHOOTING, CUSTOMER_EMAIL, screenshots). Add, do not clobber.

## Out of Scope

- Translated versions (English only for v1).
- Customer portal / SaaS deployment runner.
- AWX / Tower template export (mentioned in docs/SCALING.md).
